Design system

Gattsby design system

The visual and interaction language of Gattsby, written down once: ink, paper and signal; 48px targets and a 20px prompt for one-handed use beside a machine; and an emergency stop that is never more than one tap away.

Live readingLive readings show what the machine is reporting right now, in 32px mono so they can be read at arm’s length, each marked with how sure Gattsby is of the field.Activity feedThe activity feed is the conversation: the agent’s messages with why, the person’s answers, stage dividers, tool calls and hypothesis changes, newest at the bottom.Tool callA tool call shows one step the agent took: which tool ran, why, how long it took, what it found and a link to the raw evidence.Prompt dockThe prompt dock is the one thing the agent is waiting on: a 20px instruction, a line of detail and the answers, pinned at the bottom of the screen within reach of the thumb.Readiness checkThe readiness check lists six capabilities, each with a status word and a shape: browser, Bluetooth, on-device model, advertisement scanning, camera, storage.Evidence entryEvidence entries are the raw investigation record: every packet sent and received, every answer and every agent step, with time, direction, characteristic, bytes and the decoded meaning.Missing-tool requestA missing-tool request records a capability the agent lacked, such as decrypting a vendor’s packets, with the devices that needed it and whether it has since been built.

How to use

  1. Link the tokens, then the components:
    <link rel="stylesheet" href="tokens/tokens.css">
<link rel="stylesheet" href="assets/components.css">
  2. Use the class names on each component page; copy the HTML under each example.
  3. Read colours, sizes and durations only through tokens; re-skin a component by overriding its component tokens.
  4. Generate platform constants from tokens/tokens.json (W3C DTCG format).
  5. After any token change run check_contrast.py and tokens_to_json.py; after any page change run check_design_system.py.
  6. The mocks read these same files (docs/mocks/assets/tokens.css and ui.css import them), so a change here shows in every mock.

Safety rules outrank this system: an approval for every write or control call, the stand-clear reminder before motion, and the emergency stop on every connected screen and sheet. See Approvals and safety.
