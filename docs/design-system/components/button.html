Button

Buttons do something: send, save, start, export, delete. On a phone beside a machine they are big, few and in reach of the thumb.

WCAG 2.2 AAStatus: stable

Overview

Use a button when activating it changes something: it answers the agent, opens a sheet, starts an investigation or exports a file. Use a link when it only goes somewhere. The emergency stop is its own component: see Emergency stop.

  • Primary (ink on paper, paper on ink) is the one action the view exists for: Start, Incline is at 2%, Send. One per view.
  • Secondary (the default look) is every other action that still matters: It didn’t change, Don’t send, Export full record.
  • Ghost sits inside the app bar and sheet toolbars, almost always as an icon-only button: Back, Options, Close.
  • Danger confirms a destructive, local action (Delete all data) and only inside a confirmation sheet.

Anatomy

  1. Leading icon (optional)1.25em, inherits the label colour, aria-hidden.
  2. LabelA verb phrase in sentence case; the accessible name.
  3. ContainerAt least 48px tall (--control-height-*), --radius-md (lg: --radius-lg), 1px border.

Variants

Primary, secondary, ghost, danger: emphasis from highest to lowest; danger only inside a confirmation.
HTML
<button class="btn btn--primary" type="button">Start</button><button class="btn" type="button">It didn’t change</button><button class="btn btn--ghost" type="button">Skip</button><button class="btn btn--danger" type="button">Delete all data</button>

Icon-only

Icon-only buttons are circles, 48px, with an aria-label; the icon is aria-hidden.
HTML
<button class="btn btn--ghost btn--icon" type="button" aria-label="Back"><svg class="icon" viewBox="0 0 24 24" aria-hidden="true">…</svg></button><button class="btn btn--ghost btn--icon" type="button" aria-label="Investigation options"><svg class="icon" viewBox="0 0 24 24" aria-hidden="true">…</svg></button><button class="btn btn--icon" type="button" aria-label="Send"><svg class="icon" viewBox="0 0 24 24" aria-hidden="true">…</svg></button><button class="btn btn--primary" type="button"><svg class="icon" viewBox="0 0 24 24" aria-hidden="true">…</svg>Export profile</button>

Sizes

There is no button under 48px (NFR-009). Small only tightens padding and type; large is for the prompt and the pinned action bar.
HTML
<button class="btn btn--primary btn--sm" type="button">Small · 48px</button><button class="btn btn--primary" type="button">Medium · 48px</button><button class="btn btn--primary btn--lg" type="button">Large · 56px</button>

Small (.btn--sm): 48px tall, --space-3 padding, --font-size-sm; used for the emergency stop inside sheet toolbars. Medium: 48px, --space-4, --font-size-md. Large (.btn--lg): 56px, --space-5, --radius-lg; the prompt’s answers and the verdict’s action bar.

  • Loading (aria-busy="true") keeps the width, hides the label behind a spinner in the label colour and ignores clicks. The approval sheet’s Send shows it while the command is in flight.
  • Disabled uses the native attribute and 50% opacity. Send stays disabled until the person ticks “I am clear and know where the stop is” (FR-035); the reason is visible next to it.

Both themes

Responsive behaviour

  • Under 768px the prompt’s primary answer grows to fill its row (flex: 1 1 10rem); the secondary answer wraps beneath it when it does not fit.
  • Sheet footers stack full width on phones with the primary on top (column-reverse); from 576px they sit in one row, each taking an equal share.
  • The verdict’s action bar puts the primary on its own full-width row under 576px, then shares the row.
  • Labels never truncate. A label that wraps at 360px is too long: shorten the verb phrase.

Theming

Every variant sets five component tokens, --btn-bg, --btn-fg, --btn-border, --btn-bg-hover and --btn-bg-active, from semantic tokens. In paper the primary is ink with a paper label; in ink it flips to paper with an ink label, so the most important action is always the highest-contrast object on screen. Danger keeps its red in both themes and gains a --color-border-danger edge that reads on ink.

/* Re-skin without touching .btn */
.prompt__actions .btn--primary { --btn-bg: var(--color-accent); }

Accessibility

Role and pattern

Native <button type="button">, or type="submit" in a form. An action that navigates (Back, Options opening a routed sheet) is an <a href> with the same classes. Never a <div> with a click handler.

Keyboard

KeyAction
Tab / Shift+TabMoves to and from the button in DOM order.
Enter, SpaceActivates. Space fires on key up, so a mis-press can be cancelled by moving away.

Focus

The shared ring (--focus-ring-width 2px of --color-focus-ring, 2px offset) appears on :focus-visible only, so a tap never leaves a ring behind. On a primary button the 2px gap shows the surface, keeping the ring above 3:1 against both.

Labelling

The visible label is the name. Icon-only buttons carry aria-label naming the verb and, where needed, the object (“Leave the investigation”). Loading keeps the name and sets aria-busy; progress text goes to the nearest live region.

Motion

Background and border ease over --duration-fast; press scales to 0.98. Both disappear under reduced motion because the tokens zero the duration. The loading spinner keeps turning: it is a status.

Touch

Every button is at least 48 × 48px, with --target-gap (8px) between neighbours. Primary actions sit at the bottom of the screen on phones, in reach of the thumb (NFR-009).

Content

  • Verb phrases in sentence case: Start, Export profile, Delete all data. Never OK, Yes, Submit.
  • When a button answers the agent, it says the observed fact: Incline is at 2%, It didn’t change, not Yes / No.
  • Destructive labels name what goes: Delete all data, Delete investigation.
  • Use the specs’ words: investigation, verdict, device profile, checklist mode.
