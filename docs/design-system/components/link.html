Link

Links go somewhere: the evidence for a step, the mocks behind a device, all missing-tool requests. They are underlined ink, never colour alone.

WCAG 2.2 AAStatus: stable

Overview

Use a link to navigate. Use a button to act. Three looks exist in the mocks:

  • Inline: underlined ink inside text (“Add a location, a note or a photo before saving”).
  • Quiet (.link-quiet): a muted label with no underline until hover, used for “See all” beside a section head.
  • Evidence (.probe__evidence): an icon plus “Evidence” at the foot of a tool call, opening the raw packets for that step.

Anatomy

  1. LabelSays where it goes.
  2. Underline1px, offset 0.15em; 2px on hover.

Responsive behaviour

  • Quiet and evidence links keep a 48px tall target at every width.
  • Long link text wraps; it never truncates.

Theming

Links read --color-fg-link (ink on paper, paper on ink) and --color-fg-link-hover (signal-700 / signal-300). The underline carries the meaning, so the link never relies on hue (1.4.1).

Accessibility

Role and pattern

Native <a href>.

Keyboard

KeyAction
TabMoves to the link.
EnterFollows it.

Focus

The shared ring (--focus-ring-width 2px of --color-focus-ring, 2px offset) appears on :focus-visible only, so a tap never leaves a ring behind.

Labelling

The link text names the destination. “Evidence” sits inside a tool call whose tool name and purpose give it context; outside that context write “Evidence for this step”.

Motion

None.

Touch

Quiet and evidence links are 48px tall; inline links inside paragraphs are exempt (WCAG 2.5.8 inline exception) but never sit next to another link with less than 8px between.

Content

  • Name the destination: “See all requests”, not “Click here”.
  • External links never appear: Gattsby makes no third-party requests at run time (NFR-012).
