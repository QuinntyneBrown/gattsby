Alert and banner

Alerts tell the person something about the current screen that they need to know now: the connection dropped, the agent switched to the checklist, a form has errors, stand clear before a command.

WCAG 2.2 AAStatus: stable

Overview

  • Alert (.alert): info, success, warning, danger; icon, title, text, optional actions or dismiss.
  • Investigation banner (.inv-banner): an alert pinned above the feed (connection and mode banners, FR-006, FR-016).
  • Callout (.callout): the stand-clear reminder in an approval sheet (FR-035).
  • Status banner (.status-banner): a full-width line under the app bar (“Saved to this device”).

Anatomy

  1. IconTone colour, 20px.
  2. TitleLabel weight, tone text.
  3. TextWhat is happening and what Gattsby is doing.
  4. Spinner or dismissOptional.

Responsive behaviour

  • Banners span the feed column with 16px margins (24px from 768px); from 992px they centre at 42rem above the feed.
  • Actions wrap below the text on phones.

Theming

Each tone sets --alert-bg, --alert-fg, --alert-border and --alert-icon from its status tokens. Body text stays --color-fg-default; only the title takes the tone colour.

Accessibility

Role and pattern

role="status" for progress and mode changes; role="alert" only for failures the person must act on.

Keyboard

KeyAction
TabActions and Dismiss.

Focus

The shared ring (--focus-ring-width 2px of --color-focus-ring, 2px offset) appears on :focus-visible only, so a tap never leaves a ring behind. An error summary takes focus on submit.

Labelling

Dismiss is “Dismiss”. The icon is decorative; the title carries the tone in words.

Live ratios, light then dark.

Content

  • Title: what happened, as a sentence. Text: what Gattsby is doing about it and what the person can do.
  • Never blame the person or the device.
