Key-value list

Key-value lists show a device’s identity, the live readings in the side panel, a profile’s groups and a decoded packet.

WCAG 2.2 AAStatus: stable

Overview

  • Identity (.kv): label column 8rem (7rem narrow), values in mono so UUIDs and versions line up.
  • Readings (.readings): metric, large mono value, confidence badge.
  • Groups (.group): a profile section of keys and values with an evidence link per row.
  • Decode (.decode): field → raw → value under an evidence entry.

Anatomy

  1. Key--text-body-sm, muted.
  2. Value--text-code; wraps anywhere.

Sizes

One size.

States

Static content: no interaction states. A missing value reads “not reported” in muted text, never an empty cell.

Responsive behaviour

  • Two columns at every width; values wrap anywhere so a UUID never forces a horizontal scroll.

Theming

Keys read --color-fg-muted; values --color-fg-default; row rules --color-border-default.

Accessibility

Role and pattern

<dl> with <dt>/<dd>; readings wrap each pair in a <div>, which is valid inside dl.

Keyboard

KeyAction
—Not focusable; content is read in order.

Not focusable.

Labelling

Decode lists carry aria-label naming the layout used (“Decoded with the FTMS Treadmill Data layout”).

Contrast

Live ratios, light then dark.

Content

  • Bytes as uppercase hex with a space between bytes: 02 4E 02; UUIDs as 0x2ACD.
  • Keys are nouns in sentence case.
