Foundation

Theming

Two themes, paper and ink, built from the same roles. Themes override semantic tokens only; components never change.

WCAG 2.2 AA

  • Adding a theme
  • Preferences
  • tokens.json

Overview

Light (paper) is :root. Dark (ink) applies with [data-theme="dark"], and automatically when the OS prefers dark and the page has not forced [data-theme="light"]. Each theme sets color-scheme so native controls and scrollbars follow.

Token tiers

TierPrefixExampleWho reads it
Primitive--palette-*, --font-*--palette-ink-900Semantic tokens only
Semantic--color-*, --text-*, --space-* …--color-accentComponents and pages; themes override these
Component--btn-*, --field-*, --alert-*, --toast-*--btn-bgOne component

Adding a theme

[data-theme="high-contrast"] {
  --color-fg-muted: var(--palette-ink-900);
  --color-border-default: var(--palette-paper-500);
  color-scheme: light;
}

Override roles only, add any new pairings to contrast-pairs.json, run check_contrast.py and regenerate tokens.json.

Preferences

  • prefers-color-scheme: dark: ink, unless forced light.
  • prefers-contrast: more: borders take the strong edge; muted and subtle text become default ink.
  • forced-colors: active: the focus ring is Highlight, borders CanvasText; buttons, inputs, chips and badges draw a system border.
  • prefers-reduced-motion: see Motion.

tokens.json

tokens/tokens.json is generated from tokens.css in the W3C Design Tokens (DTCG) format: $type, $value, aliases as {group.token}, dark overrides under $extensions. Regenerate it after any change:

python .claude/skills/extracting-design-systems/scripts/tokens_to_json.py docs/design-system/tokens/tokens.css

Do and don’t

  • Do re-skin a component by overriding its component tokens.
  • Don’t read a palette token in a component.
  • Don’t invert light values for dark; build dark from the roles.
