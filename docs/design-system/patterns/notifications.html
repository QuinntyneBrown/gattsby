Notifications

Toast versus banner, priority, timing and dismissal.

Overview

Two kinds: banners (about this screen, persistent until resolved) and toasts (about something that finished, brief). There is no notification centre.

When to use

EventKindToneDismiss
Connection dropped / reconnectingBannerwarningWhen reconnected
Couldn’t reconnectBannerdangerTry again
Running as a checklistBannerinfo / warningDismiss
Export savedToastsuccess8 s
Storage nearly fullToastwarningDismiss
Couldn’t save noteToastdangerRetry or Dismiss

Structure

Continuing as a checklist.

The on-device model stopped answering twice in a row. Everything found so far is kept; you pick the next steps.

Couldn’t save your note.
Storage is full. Your note is still in the box — make room, then save again.
Mode banner and danger toast.

States

Stacked toasts: at most three, newest at the bottom; older ones collapse.

Responsive behaviour

  • Banners span the feed column; toasts full width under 576px, 24rem from 576px.

Accessibility

  • Polite status for progress and success; alert only for failures that need action.
  • Toasts pause on hover and focus; errors never auto-dismiss.

Content

  • Title: the event. Text: what Gattsby is doing and what the person can do.
